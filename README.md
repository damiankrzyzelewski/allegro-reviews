# Polish Review Rating Predictor

Give it a Polish product review, get back a 1–5 star rating.

The model is [HerBERT](https://huggingface.co/allegro/herbert-base-cased) fine-tuned on the Allegro Reviews dataset (part of the [KLEJ benchmark](https://klejbenchmark.com/)), exported to ONNX and quantized to INT8 so it runs on a plain CPU. It's served by a small FastAPI app on Google Cloud Run, with a Streamlit frontend on top.

[![Streamlit App](https://static.streamlit.io/badges/streamlit_badge_black_white.svg)](https://reviews-ui-fqmt89hrbgqq5rsqzx4vxe.streamlit.app/)
[![GCP Cloud Run](https://img.shields.io/badge/GCP-Cloud%20Run%20Docs-blue?logo=google-cloud&logoColor=white)](https://polish-reviews-api-706649204585.europe-west1.run.app/docs)

The research part (EDA, baselines, fine-tuning, distillation, quantization) lives in `notebooks/allegro-reviews.ipynb`. This repo is what came out of it: the model behind an API that anyone can call.

```
│ Streamlit Cloud (Frontend UI) │
└───────────────┬───────────────┘
                │  HTTPS POST /predict
                ▼
┌─────────────────────────────────────────────────┐
│  Google Cloud Run (Serverless Docker)           │
│                                                 │
│  ┌───────────────────────────────────────────┐  │
│  │  FastAPI (validation, OpenAPI docs)       │  │
│  └─────────────────────┬─────────────────────┘  │
│                        │                        │
│  ┌─────────────────────▼─────────────────────┐  │
│  │  Inference engine (no PyTorch)            │  │
│  │  • tokenizers (Hugging Face, Rust)        │  │
│  │  • ONNX Runtime (C++, INT8)               │  │
│  └─────────────────────┬─────────────────────┘  │
└────────────────────────┬────────────────────────┘
                         │  downloaded on boot
                         ▼
            ┌─────────────────────────┐
            │ Hugging Face Model Hub  │
            │  • tokenizer.json       │
            │  • model_quantized.onnx │
            └─────────────────────────┘
```

A few decisions worth explaining:

- Tokenization is handled by the `tokenizers` library and inference by ONNX Runtime, so the image stays a lot smaller than a typical Transformers one.
- The container pulls `tokenizer.json` and `model_quantized.onnx` from the Hugging Face Hub when it starts. That keeps the image small, but it means a cold start is a bit slower than a warm request.
- **Cloud Run** because the traffic is spiky and it scales to zero when nobody is using it.

## The model

The deployed model is `herbert_ordinal_teacher_quantized` from the notebook: `allegro/herbert-base-cased` fine-tuned with an ordinal head, then quantized.

**Ordinal head instead of plain regression.** Rather than predicting one number, the model answers four yes/no questions: is the rating above 1? above 2? above 3? above 4? It's trained with binary cross-entropy on those four outputs. At inference time each output goes through a sigmoid, and the final rating is 1 plus the number of questions answered "yes". This ended up better than regressing the rating directly with the same backbone (0.501 vs 0.541 wMAE in FP32).

**Quantization.** The fine-tuned model was exported to ONNX and dynamically quantized to INT8 with Hugging Face Optimum (AVX2 config), which is what Cloud Run CPUs are happy with. Quality drops slightly (0.501 → 0.536 wMAE), and the model no longer needs a GPU.

### Metric

Results are reported as **wMAE**: the mean absolute error computed separately for each true star rating, then averaged. The dataset is imbalanced, so a plain MAE would reward a model that mostly gets the common classes right. wMAE doesn't let it get away with that.

### Results

All numbers are on the KLEJ AR dev set (lower wMAE is better).

| Model | wMAE | Notes |
|---|---|---|
| Predict the mean rating | 1.292 | Baseline |
| DAN + fastText embeddings | 0.838 | Worse than TF-IDF + Ridge |
| TF-IDF (word + char + hand-made features) + Ridge | 0.718 | Best classical model |
| HerBERT, regression head (FP32) | 0.541 | |
| HerBERT, ordinal head (FP32) | 0.501 | Best overall, needs a GPU to be comfortable |
| **HerBERT, ordinal head (ONNX INT8)** | **0.536** | **Deployed.** MAE 0.460, exact match 60.7% |
| Tiny HerBERT (3 layers), ordinal, distilled (ONNX INT8) | 0.595 | Smaller and faster, but less accurate |

I distilled the model into a 3-layer student. It's smaller and faster, but the full-size quantized model is more accurate, and that's the one deployed.

## API

`POST /predict`

```bash
curl -X POST https://polish-reviews-api-706649204585.europe-west1.run.app/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "Produkt jest świetny, polecam każdemu!"}'
```

```json
{
  "rating": 5
}
```

Interactive docs are generated by FastAPI at `/docs`.

## Running locally

```bash
docker build -t review-rating-api .
docker run -p 8080:8080 review-rating-api
```

Then open `http://localhost:8080/docs`. The first start downloads the model from the Hub, so give it a moment.

The Streamlit app takes the review text, sends it to `/predict` and shows the result.

## Limitations

- **Mixed or sarcastic reviews are hard.** In my tests, "Wygląda świetnie, trzyma się solidnie, szkoda tylko że w ogóle nie działa" got a 4, though most people would give it a much lower score because the product doesn't work. The model tends to follow the overall tone rather than the one sentence that matters.
- **Exact match is about 61%.** Being off by one star is common (MAE is 0.46). Treat the output as a good estimate, not ground truth.
- **Inputs are limited to 256 tokens**, which is what the model was trained with, so very long reviews get truncated.
- **No held-out test set.** The KLEJ test split doesn't come with labels, so the dev set was used both for early stopping and for the numbers above. Expect real-world performance to be slightly worse than reported.

## Explainability & Feature Attribution (LIME)

To understand what drives the model's predictions, I applied [LIME](https://github.com/marcotcr/lime) directly to the INT8 quantized ONNX model. LIME perturbs the input by masking individual clauses/segments and measures the resulting shift in the predicted score.

The test review was intentionally crafted with conflicting sentiments: a phenomenal camera and build quality, paired with poor battery life, a lagging system, and an excessive price point. The model predicted **4 / 5 stars**.

### How to interpret this explanation:
1. **Ordinal Mapping to 0–1 Scale:**  
   LIME natively expects probability-like values. Since this is an ordinal regression/classification setup, the expected rating ($$1 + \sum_{k=1}^4 \sigma(\text{logit}_k)$$) is normalized into the range $$[0, 1]$$.  
   The **0.77** score for *"Higher Rating"* translates directly back to the 5-star scale:
   $$\text{Predicted Rating} \approx 1 + (4 \times 0.77) = 4.08 \rightarrow \mathbf{4 \text{ stars}}$$

2. **Feature Weights & Intercept:**  
   The bars indicate local contributions relative to the explainer's baseline:
   - **Strong Positive Driver (+0.27):** The opening clause (*"Aparat robi fenomenalne zdjęcia w dzień i jakość wykonania obudowy naprawdę zachwyca"*) carries an exceptionally strong positive weight.
   - **Negative Pulls (-0.27 combined with minor clauses):** The critique regarding battery life, system sluggishness, and high price drags the score down from an otherwise certain 5.0 rating, settling the overall prediction at a solid **4/5**.
